# 设备互联（Device Link）

以聊天会话的方式连接 macOS、Windows、Linux 与手机浏览器，实时分享文本、链接、图片和任意格式文件。

## 当前能力

- 桌面端聊天式会话与移动端自适应 Web 客户端。
- ZTools 的固定命令、任意文本、图片、文件/目录四类入口。
- 局域网自动选择地址，支持二维码连接，也可直接在手机浏览器打开电脑地址后输入匹配码。
- 6–12 位匹配码；默认每次随机生成，也可在设置中自定义。
- 二维码一次性密钥 + 匹配码的 PBKDF2 挑战证明。
- 连续输错 5 次锁定 10 分钟，成功配对后旧二维码立即作废。
- 首次授权后保存独立设备凭据；刷新页面或电脑端服务重启时自动完成挑战响应，无需重复输入匹配码。
- 每台设备独立会话密钥；WebSocket 消息和文件分块使用 AES-256-GCM。
- 每台设备自动建立单独会话，并提供全部已授权设备共同参与的共享会话；电脑和手机都可随时切换。
- 私聊消息、历史与附件均在服务端按设备校验，只有共享会话内容会跨设备分发。
- 4 MiB 流式分块传输、失败重试、实时进度和边传边算完整性摘要；默认接收上限 10 GB，可配置至 1 TB。
- 电脑端可直接把文件或文件夹拖入会话区域发送，兼容 Electron 新旧文件路径接口。
- 会话支持浮层搜索与手动清理历史；清理时仅删除消息和插件接收的本地附件，保留设备配对与同步设置。
- 传输任务有全局/单设备并发限额，30 分钟无活动自动清理，不完整文件不会长期占用磁盘。
- 文本与附件一键复制/打开，设备授权可随时撤销。
- 加密 WebDAV 离线同步，附件逐块加密且不设 64 MiB 人工上限；删除墓碑防止离线设备恢复已删消息。

## 安全边界

匹配码不会直接提交到服务端。扫码时，手机从二维码 URL 片段取得一次性高熵密钥，并与匹配码共同派生证明；直接打开电脑地址时，则使用服务端当前代次的临时手动连接密钥与匹配码派生证明。HTTP 握手中可见的临时会话令牌本身不能解密消息或文件。内容使用独立会话密钥加密。

首次配对会为浏览器签发独立的长期设备凭据：手机将其保存在当前地址对应的浏览器本地存储中，电脑端使用系统安全存储加密后持久化。后续访问只发送两分钟内有效且不可重放的挑战签名，再换取新的 24 小时会话密钥；从电脑端移除设备会立即使该凭据失效。更换浏览器、清理站点数据，或电脑的 IP/端口导致访问地址变化时，需要重新配对。

当前 Web 客户端只在页面前台工作。Android/iOS 的后台剪贴板读取、通知镜像、相册后台备份和系统分享菜单需要原生伴侣应用，不能由 ZTools 插件或普通浏览器页面可靠完成。

手机发送超大文件时只保留一个分块在内存中。电脑向手机发送时，支持 File System Access 的浏览器会直接写入用户选择的文件；局域网 HTTP 下无法使用该 API 时，超过 128 MiB 的内容会逐块暂存到 IndexedDB，再交给浏览器下载，避免把整份文件堆进 JavaScript 内存。最终可接收大小仍受手机剩余空间、浏览器存储配额和系统下载限制影响。

局域网 HTTP 不属于浏览器安全上下文，因此移动页内置随插件离线分发的 Noble AES-GCM/PBKDF2 后备实现，不依赖 CDN。二维码模式通过未进入 HTTP 请求的 URL 片段提供更强的首次配对保护；手动模式主要解决无法扫码的可用性问题，仍有匹配码错误锁定，但不具备二维码高熵密钥对同等级的抗旁路监听能力。在不可信局域网中应优先扫码。普通浏览器无法在零配置条件下验证本机自签名 HTTPS，具备主动中间人能力的攻击者仍可能篡改首次加载的 HTTP 页面。高对抗环境需要后续原生伴侣应用或受信任证书部署。

WebDAV 只用于离线补拉与历史同步，不承担实时通道。同步索引、文件名、消息正文和附件均在本机加密后上传；同步密码不会发送给 WebDAV 服务。

## 开发

```bash
npm install
npm test
npm run build
```

构建产物位于 `dist/`。构建脚本会把 preload 运行时需要的 WebSocket 与二维码依赖及其传递依赖复制到 `dist/preload/node_modules`；局域网服务使用 Node 原生 HTTP 实现。
